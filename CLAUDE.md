# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

PhishDriftBench + DASH: a four-axis evaluation protocol (Time, Source, Provenance, Evasion) for
phishing-URL detectors, applied to five reimplemented baselines drawn from a ten-paper corpus,
plus DASH (Drift-Aware Selective Hardening), a proposed lightweight mitigation. URL-only — no
page is ever fetched, rendered, hosted, or transmitted.

Start with [RESEARCH_GAP_AND_IMPROVEMENTS.md](RESEARCH_GAP_AND_IMPROVEMENTS.md) for the research
gap and the actual results; [docs/GAP_ANALYSIS.md](docs/GAP_ANALYSIS.md) for the base-paper corpus and gap
decisions; [README.md](README.md) for setup and repository layout.

## Setup and commands

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
```

macOS also needs `brew install libomp` for XGBoost/LightGBM/CatBoost (see
[docs/threading-notes.md](docs/threading-notes.md)).

```bash
# Full test suite (pytest.ini sets pythonpath=src and testpaths=tests, so no env var needed)
pytest

# Single test file / single test
pytest tests/test_lexical.py
pytest tests/test_lexical.py::test_shannon_entropy_empty_string_is_zero -q

# Sanity check: whole pipeline on synthetic data
PYTHONPATH=src python scripts/smoke_test.py

# First check against real data, once datasets are acquired into data/raw/
PYTHONPATH=src python scripts/real_data_check.py

# Any experiment script (see scripts/README.md for the full index)
PYTHONPATH=src python scripts/run_axis_t.py

# Interactive demo (CLI or web)
PYTHONPATH=src python scripts/demo_cli.py
PYTHONPATH=src python webapp/app.py   # http://127.0.0.1:5001
```

Datasets (PhishTank, PhiUSIIL, Tranco) and everything under `results/` and `data/processed/` are
gitignored — they're either too large for git or are regenerated by the scripts.
`reference_papers/` (base and excluded reference PDFs) is also gitignored: those are other
authors' copyrighted papers, kept locally only, never pushed.

## Architecture

`src/phishdriftbench/` is the implementation; `scripts/` are the experiment drivers that call into
it and write CSVs to `results/`. Each subpackage:

- **`bench/`** — the benchmark protocol itself. `splits.py` builds Axis T (temporal) and Axis S
  (cross-source) splits and applies prevalence correction; `evasion.py` is Axis E1 (rule-based,
  label-preserving URL transforms — homoglyph substitution, padding, TLD swap, etc., all offline,
  no network); `generator.py` is Axis E2 (a URL generator trained on real PhishTank text).
- **`features/`** — `lexical.py` computes P1 static-lexical features (no network access);
  `normalize.py` does homoglyph normalization (the fix for the one real Axis E1 vulnerability
  found: homoglyph substitution cost baseline B3 2.75 recall points).
- **`provenance/taxonomy.py`** — classifies every feature as P1 (static-lexical), P2
  (lookup-at-inference: WHOIS/DNS/SSL/domain-age), or P3 (third-party reputation), and includes
  `LiveLookupClient` for acquiring real P2 data.
- **`models/baselines.py`** — five reimplemented baselines, each a `fit(X, y) -> model` /
  `predict(model, X) -> np.ndarray` pair matching the contract `bench/splits.py` and
  `eval/isolated_run.py` expect:
  - B1 — CatBoost over lexical features (Kustiawan & Ghauth)
  - B2 — layered brand-jacking screen + lexical ML (Goenka et al.)
  - B3 — Residual MLP / ResMLP (Remya et al.)
  - B4 — cross-dataset XGBoost over feature intersection (X-PHIDE)
  - B5 — BERT + LightGBM hybrid (BGL-PhishNet; the GNN component is explicitly *not*
    implemented — under-specified in the source paper)
- **`models/novelty.py`** — B7, a zero-day novelty gate addressing what no amount of retraining
  B1-B6 fixes: a supervised classifier can't recognize patterns absent from training data.
- **`models/preprocessing.py`** — the mandatory cleaning pipeline for B6 (Cascade-DASH):
  deduplication (PhishTank has a 19.4% near-duplicate rate) + homoglyph normalization.
- **`dash/`** — `stability.py` scores each feature's drift-stability (temporal + cross-source PSI
  plus importance variance); `dash.py` combines stability-weighted training, drift detection, a
  bounded active-labelling budget, and a calibrated abstention band into DASH itself.
- **`eval/`** — `bootstrap.py` computes nonparametric bootstrap CIs backing every headline number
  in the paper draft; `dedup.py` is the exact/near-duplicate leakage probe; `isolated_run.py` runs
  each baseline's fit+predict in its own subprocess (see constraint below).
- **`demo/model.py`** — a separate, ordinary train-once/save/load model for the interactive CLI
  and web demo. Deliberately *not* one of the paper's B1-B5 baselines.

### Critical constraint: process isolation for GBM/DL libraries

CatBoost, XGBoost, LightGBM, and PyTorch each bundle their own OpenMP-style threading runtime.
Running CatBoost fit → XGBoost fit → PyTorch train/predict back-to-back in one process deadlocks
(reproduced even on tiny synthetic data; capping thread counts does **not** prevent it — it's a
cross-runtime interaction, not resource contention). Every baseline caps its thread count anyway,
but the actual fix is `eval/isolated_run.py`, which runs each baseline in its own short-lived
`ProcessPoolExecutor` subprocess (`spawn` start method). Never call more than one of
{CatBoost, XGBoost, LightGBM, a PyTorch-using baseline} sequentially inside one long-lived
interpreter — always go through `isolated_run.py`. Full root-cause writeup in
[docs/threading-notes.md](docs/threading-notes.md).

### `scripts/` is flat by necessity, not neglect

Many `scripts/run_*.py` files import each other directly as sibling modules (e.g. `run_v7_final.py`
does `import run_b6_experiments as b6`), relying on Python putting a script's own directory on
`sys.path` when run directly. `run_b6_experiments.py` alone is imported by 9 other scripts. Do
**not** move scripts into subfolders — it breaks these imports. See
[scripts/README.md](scripts/README.md) for a grouped index (axis evaluations, B6/B7/v7 variants,
DASH, provenance audit, demo training, figures, leakage probes, sanity checks) that documents
without restructuring.

### Demo model versioning

`scripts/train_demo_v7.py` through `train_demo_v10.py` are successive retraining recipes for the
interactive demo model, kept for history rather than deleted — each one fixed a specific measured
failure in the previous version (see the changelog inside `train_demo_v10.py` and README's mention
of v8's documented failures). `v10` is current; `data/processed/demo_model*_backup/` holds prior
versions.
